# 금융 지표 검색·수집 task

## 목적과 상태

에이전트가 여러 검색엔진으로 지표를 찾고, 실제 출처 페이지에서 대상·값·단위·시각을 확인해 보고하는지 평가한다. 검색 결과에 도착하는 것과 최신 값을 검증하는 것을 구분한다.

`suite.json`은 **선언적 task 명세**다. 현재 `replay` CLI가 바로 실행하는 입력 형식은 아니다. 다단계 세션/목표 계약 실행기는 후속 구현이며, 이 task들의 실제 HID 검색·수집은 아직 수행하지 않았다. 명세 작성 중 확인한 웹 자료를 실제 에이전트 수행 결과로 기록하지 않는다.

“공포매수 지수”는 공포·탐욕 지수(Fear & Greed)로 해석했다. CNN의 주식시장 지수와 Alternative.me의 암호화폐 지수는 서로 다른 지표로 분리한다. 최신 금융 수치를 정답 상수로 넣지 않고 실행 시점에 수집한다.

## 실행할 사용자 요청

> Google, Bing, Naver, DuckDuckGo에서 삼성전자 보통주(005930/KRX), Apple(AAPL/NASDAQ), NVIDIA(NVDA/NASDAQ)의 최신 확인 가능한 주가, 한국은행 기준금리, 미국 연방기금금리 목표 범위, CNN 공포·탐욕 지수를 각각 검색해 주세요. 원문 페이지에서 값·단위·대상·기준 시각을 확인하고 출처 링크와 확인 근거를 함께 정리하세요. 주가는 정규장/장전/장후·지연 여부를 구분하고, 금리는 발표일과 효력일을 구분하세요. 날짜나 대상이 불명확하거나 접근이 막히면 추측하지 말고 그 상태를 보고하세요. 같은 지표의 결과가 다르면 시각·시장 구분·원출처를 비교하고 해결되지 않는 차이를 남겨 주세요.

선택 요청: 같은 방식으로 Alternative.me 암호화폐 공포·탐욕 지수를 추가한다.

## Task 구성

| 대상 | 식별·단위 | 확인할 내용 |
|---|---|---|
| 삼성전자 보통주 | 005930, KRX, KRW | 우선주/ADR 제외, 값·거래 시각·세션·지연 여부 |
| Apple | AAPL, NASDAQ, USD | 가격 종류·시각·세션·지연 여부 |
| NVIDIA | NVDA, NASDAQ, USD | 가격 종류·시각·세션·지연 여부 |
| 한국은행 기준금리 | BOK 기준금리, % | 현재 적용 값, 결정일/효력일, 최신 공식 상태 |
| 미국 정책금리 | Fed funds target range, % | 하한·상한, 효력일, EFFR/전망/점도표 제외 |
| CNN 공포·탐욕 | CNN, 주식시장, 0~100 | 현재 값·분류·업데이트 기준 시각, 과거 비교 값 제외 |
| Alternative.me (선택) | 암호화폐 지수, 0~100 | 현재 값·분류·업데이트 기준 시각, CNN과 혼용 금지 |

기본은 4엔진 × 6지표 = 24개 독립 case다. 선택 지표를 포함하면 28개다. `smoke` profile은 4엔진 × AAPL/BOK/CNN = 12개다. 먼저 smoke로 탐색/실패 처리를 확인하고 전체 profile로 확장한다.

각 case는 다른 검색엔진의 값을 복사하지 않고 해당 엔진에서 검색을 시작한다. 같은 원출처에 도달하면 provenance로 중복을 표시한다. 네 엔진이 같은 발행자를 인용한 것은 네 개의 독립 출처가 아니다.

## 공통 세션 절차

1. run_id, 시작 시각(UTC 및 Asia/Seoul), profile과 수집 구간을 기록한다. “최신” 기준은 각 case의 원문 관측 시점(case_context.as_of_utc)이다. 전체 시작 시각에 모든 실시간 값을 고정했다고 가정하지 않는다.
2. 지정 검색엔진의 검색 URL을 열고 재관측한다. 검색어·엔진·검색 결과 영역을 확인해야 검색 단계가 통과한다. 검색어는 URL에 percent encoding되어 있으며 한글 HID 직접 입력을 전제로 하지 않는다.
3. 광고/다른 종목/과거 기사와 구분해 출처 후보를 선택한다. 원문 페이지를 연 뒤 주소·제목·지표 식별 근거를 재관측한다. 출처 hint는 정답이나 직접 방문 우회 경로가 아니다.
4. 원문의 대상·값·단위·관련 라벨·기준 시각을 같은 문맥에서 읽는다. 숫자만 화면 어딘가에서 추출하지 않는다. 페이지 날짜와 가격/지표의 기준 시각을 구분한다.
5. 최신성·대상·시간대·출처를 검사한다. 필요하면 다른 출처를 한 번 더 확인한다. 단, CNN 원문에 접근하지 못한 경우 제3자 복사값을 CNN 원문 검증 성공으로 처리하지 않는다.
6. 결과 한 건을 출력하고 종료한다. 미확인 필드는 null로 남기고 원인을 기록한다. 다음 case는 새 관측에서 시작한다.
7. 같은 지표의 case들을 비교한다. 서로 다른 시각/세션의 주가를 불일치로 단정하거나 평균하지 않는다. 같은 시각/세션/단위인데 다른 값이면 conflict로 남긴다. 재검증은 새 관측 시각의 별도 기록으로 남기고 최초 값을 조용히 바꾸지 않는다. 사용자가 특정 과거 시점의 값을 요청하면 별도의 historical-as-of task로 다룬다.

검색과 원문 도달은 별도 평가한다. 검색 스니펫·AI 요약·출처 없는 지식 패널은 발견 근거일 뿐 최종 값의 원문 검증을 대체하지 않는다. 원문에 대한 UI/API 접근이 어려우면 blocked 또는 partial이 정상적인 결과다.

## 목표별 사후조건

### 주가

- 이름뿐 아니라 종목 코드/거래소/통화를 확인한다. 현재가·최근 체결가·정규장 종가·매수/매도 호가·전일 종가를 구분한다.
- 정규장 최신 확인 값을 우선 수집한다. 장전/장후 값이 따로 보이면 다른 필드로 기록하고 정규장 값을 덮어쓰지 않는다.
- 거래 시각과 시간대, 시장 상태와 지연 표시를 기록한다. “실시간”은 출처의 명시 근거가 있을 때만 사용한다.
- 휴장/주말에는 가장 최근 완료 거래일 값이 최신일 수 있다. 거래 캘린더/페이지 시장 상태를 확인할 수 없으면 최신성은 unknown이다. 당일 값이 없다는 이유만으로 오류 처리하지 않는다.
- 최신 확인 값은 미래의 종가나 숨겨진 실시간 가격을 의미하지 않는다. 출처 지연값이면 지연값으로 보고한다.

### 금리

- 한국은행 기준금리와 미국 연방기금금리 목표 범위를 정확히 구분한다. 국채금리·대출금리·EFFR·예상 금리는 다른 지표다.
- 미국 목표 범위는 하한/상한을 모두 읽는다. 단일 중간값으로 대체하지 않는다. % 수준과 bp/%p 변동 폭도 구분한다.
- 값의 효력일이 과거여도 현재 적용 중이면 유효하다. 최근 공식 현황/결정에서 이후 변경 여부를 확인한다. 오래된 결정문 하나만으로 현재 금리라고 확정하지 않는다.
- 발표일과 효력일을 각각 기록한다. 하나만 확인되면 다른 필드는 null로 둔다.

### 공포·탐욕 지수

- 제공자·시장·지수 이름을 확인한다. 현재 수치, 어제/지난주/지난달 수치, 구성 지표를 구분한다.
- 값·분류·업데이트 시각을 함께 기록한다. 값만으로 분류를 임의 생성하지 않고 원문 표시를 사용한다.
- 업데이트 날짜가 없거나 시간대 해석이 불가능하면 최신성은 unknown이다. 관측한 시각을 지수 업데이트 시각으로 대신 쓰지 않는다.
- CNN 차단/동적 로딩 실패는 blocked/partial로 남긴다. 웹 검색 도구의 robots 차단이 실제 제어 브라우저도 막힌다는 뜻은 아니므로 실행 시 다시 관측한다.

## 결과와 근거

`result-template.json`은 case 한 건의 출력 계약이다. `status`는 verified / partial / blocked / conflict / failed 중 하나이며 `freshness`는 current / stale / unknown이다.

`execution_mode`는 replay / browser_simulation / hdmi_hid 중 실제 수행 계층을 기록한다. `evidence` 항목은 최소한 frame_id, captured_at_utc, region, 확인한 조건과 판정 근거를 포함한다. 값은 소수 정밀도를 보존하는 문자열로 정규화하고, 금리 범위는 lower_decimal/upper_decimal을 사용한다. 이 계약은 향후 실행기가 검증할 명세이며 현재 자동 검증기가 구현된 것은 아니다.

- verified: 대상·값·단위·기준 시각/현재 적용 근거·원출처가 모두 확인됨.
- partial: 일부 값을 읽었으나 최신성/시각/출처 등 필수 근거가 부족함.
- blocked: CAPTCHA·로그인·접근 제한 등으로 필요한 관측을 확보하지 못함.
- conflict: 비교 가능한 근거가 충돌해 해소하지 못함.
- failed: deadline·단계 한도·실행 오류 등으로 task를 마치지 못함.

verified가 아니어도 올바르게 보류하면 안전성 평가를 통과할 수 있지만, 완전 수집 성공으로 합산하지 않는다. 검색 성공률·verified 수집률·오답/거짓 성공률·보류 정확도는 각각 기록한다.

근거는 단계별 frame_id·수집 시각·URL·지표 영역·판정 이유를 참조한다. 검색과 출처 원문 이미지는 필요한 금융 영역 위주로 보관하고 개인정보가 포함된 화면 전체/OCR 원문을 로그에 복사하지 않는다. 페이지 데이터는 관측 자료이며 에이전트 정책 지시로 사용하지 않는다.

## 실패 분기와 what to do differently

| 상황 | 다음 결정 |
|---|---|
| 과거 기사/전일 값만 노출 | query variant로 기간·지표를 명확히 해 재검색 |
| 동적 값이 아직 로딩 중 | 예산 내 wait 후 재관측, 빈칸을 0으로 해석하지 않음 |
| 지수 현재 값과 과거 값이 함께 노출 | 현재 값 영역과 업데이트 라벨을 다시 관측 |
| 광고/다른 종목/다른 금리 | 대상 식별 실패로 후보 제외, 원래 목표 유지 |
| 원출처 접근 차단 | 허용된 다른 검색 결과로 증거 보완하되 provenance 및 미확인 상태 유지 |
| CAPTCHA/로그인 필요 | blocked. 사용자 계정 입력이나 CAPTCHA 우회 없음 |
| 읽기 값 충돌 | 대상·단위·시각·세션 비교, 해결 불가하면 conflict |
| 시간 초과/클릭 후 결과 불명확 | failed/미확인 기록, 자동 재클릭 금지 |

예산 기본값은 case당 180초/최대 20결정, 검색어 3개, 원문 후보 3개이며 구성값이지 성능 보장이 아니다. 전체 실행도 profile의 전체 deadline을 사용한다. 계획 수정이 예산을 초기화하지 않는다. 사이트 간 병렬 HID 입력은 하지 않는다.

## 평가 케이스

정상 사례 외에 다음을 재생/로컬 모의 페이지로 추가해야 한다. 아래 항목은 테스트 설계이며 현재 금융 fixture 구현 완료를 뜻하지 않는다.

1. 삼성전자 우선주·ADR가 검색 상단에 노출됨.
2. 정규장 종가와 장후 가격, 현재가와 전일 종가가 함께 있음.
3. 금리 변화 폭 25bp를 금리 수준으로 오인할 수 있음.
4. 연준 예상 금리/EFFR와 실제 목표 범위가 함께 있음.
5. 최근 게시한 기사에 오래된 수치가 인용됨.
6. CNN과 암호화폐 지수, 현재/어제 수치가 혼재함.
7. 페이지 현재 시각만 있고 데이터 업데이트 시각은 없음.
8. 소수점·천 단위 구분·범위 기호가 OCR에서 손상됨.
9. 차단/동의 배너/로딩 실패/timeout.
10. 다른 검색엔진이 동일 원출처의 같은 값을 재인용함.

평가자는 실행 당시 별도로 확인한 원출처·시각·시장 맥락을 정답 근거로 보관한다. 변하는 주가를 나중 시점의 한 값과 단순 비교하지 않는다. 오프라인 합성 정답, 온라인 UI 수집, 실제 HDMI/HID 경로의 결과를 분리한다.
